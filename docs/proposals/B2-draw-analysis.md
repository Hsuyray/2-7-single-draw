## 1. 換牌動作對應 [確認]

`tests/test_draw_mapping_properties.py`(9 個測試，全過):
- 每手牌的 32 個實際換牌動作 ↔ bucket 動作是一對一，來回轉換不變，`draw_count` 相同(400 手隨機牌)。

結論：對應與 `draw_count` 編碼沒有發現錯誤。

## 2. 發現的問題

### 2.1 bucket 看不到順子聽牌結構 [確認],但對換牌決策的影響**尚未證實**(day57 更正)
`DrawHandBucket` 只存點數級別(2-3、4-5、6-7、8-9、T-J、Q-K-A),所以 3-4-5-6-8 與 2-4-5-7-8 同一個 bucket,8-5-4-3-2 與 9-5-4-3-2 也同一個 bucket。

**更正**:原稿寫「3-4-5-6-8 應丟 6」是錯的(使用者指出)。精確列舉所有補牌後的攤牌勝率(平手算一半):

| 手牌 | 對手 | pat | 換一張的最佳選項 |
|---|---|---|---|
| 8-6-5-4-3 | 拿 7-5-3-2 換一張 | **0.860** | 0.459 |
| 8-6-5-4-3 | pat 9-7-6-4-2 | **1.000** | 0.214 |
| 8-7-5-4-2 | 拿 7-5-3-2 換一張 | **0.767** | 0.471 |
| 9-5-4-3-2 | 拿 7-5-3-2 換一張 | **0.744** | 0.446 |
| 8-5-4-3-2 | 拿 7-5-3-2 換一張 | **0.837** | 0.464 |

這些手牌全部都該 pat,差距很大，所以在這些情境下 bucket 合併**不影響**換牌選擇。原稿「705 個丟牌中 65 個在 bucket 內結論不一致」把不會被考慮的丟牌(拆成牌)也算進去，高估了問題，已撤回作為證據。

8 與 9 合併的影響主要在**下注**:同樣面對換一張的對手,8-5-4-3-2 pat 0.837、9-5-4-3-2 pat 0.744。

**正確的量法**:`scripts/inspect_draw_equity.py`(day57)。對每個 bucket、在一組參考情境下，用精確補牌勝率找出每手成員牌的最佳選項，量「bucket 遺憾值」:所有成員被迫用同一個 bucket 動作時，每手牌損失的勝率。勝率只看攤牌、不含下注，是換牌選擇的一階參考，不是 solver 的 EV。

**第一批結果(made 9 以下的 52 種無對子牌，選項 = pat / 換 1 / 換 2)** [確認，但僅限「對手是已知一手牌、忽略位置」,見 2.1b]:

| 情境 | 手牌加權平均遺憾值 | 最大遺憾值 > 0.05 的 bucket | 最佳選項 pat / 換1 / 換2 |
|---|---|---|---|
| 對手 pat 9-7-6-4-2 | 0.011 | 1 / 16 | 29 / 23 / 0 |
| 對手 pat 8-6-4-3-2 | 0.013 | 3 / 16 | 6 / 31 / 15 |
| 對手 pat 7-6-4-3-2 | 0.003 | 1 / 16 | 5 / 20 / 27 |
| 對手換 1 張到 7-5-3-2 | 0 | 0 / 16 | 52 / 0 / 0 |
| 對手換 1 張到 8-6-4-2 | 0 | 0 / 16 | 52 / 0 / 0 |

讀法:
- 對手抽牌時，這些成牌全部該 pat,bucket 合併沒有損失。
- 對手 pat 時，決策取決於能不能贏過對手的 pat,8 與 9 的差別變得關鍵。最大的例子:bucket `(0,0,1,2,3)` 面對 pat 8-6-4-3-2,8-6-4-3-2 自己該 pat(平手),9 開頭的成員該拆 9,被迫同一動作時最大損失 0.381。
- 這些數字是對「已知的一手 pat 牌」,實際對手 pat 的是一個 range,損失會被平均而變小;所以目前證據顯示 bucket 的換牌損失集中在「面對對手 pat、8 / 9 邊界」的少數 bucket,不是全面性的問題。
- 待補：全部 1,278 種無對子牌(含需要換 1–2 張的聽牌手)的結果。

### 2.1b 上面的勝率表有兩個根本限制(day57,使用者指出)[確認]
1. **對手的牌是已知的**:表中「對手 pat 9-7-6-4-2」是一手固定牌。實際上我們只看得到對手的動作(下注、跟注、換幾張),只能推出一個範圍(range)。
2. **沒有處理位置**。程式碼確認的行動順序(button = seat 0):

| 階段 | 先 | 後 |
|---|---|---|
| predraw 下注 | button | 大盲 |
| 換牌 | **大盲先換** | button,看得到大盲換幾張 |
| postdraw 下注 | **大盲先行動** | button |

   - button 換牌時已經知道對手換幾張，可以依此決定。
   - 大盲換牌時不知道對手會怎麼換;button 會**根據大盲換幾張**再決定，所以大盲的選擇會改變對手的反應(例如大盲 pat 可能讓 button 拆掉邊緣的成牌)。這也是 snow(爛牌 pat 詐唬)可能正確的原因，純攤牌勝率完全看不到。
   - 換牌後的下注，大盲先行動，處於資訊劣勢。

因此 2.1 的表只能當「固定對手牌、忽略位置」的初步結果，不能拿來判斷某個換牌決策對錯，也不能單獨決定 P2。

### 2.1c 重新設計：每個實際換牌決策的「選項價值」(待核准)
在 self-play 打到的每個換牌決策(和 benchmark 同一批牌)上，對每個換牌選項估計:

**Q(選項) = 我方採取這個選項之後，雙方都照 checkpoint 的策略打完，我方的期望 chips。**

計算方式(Monte Carlo,只用公開資訊，不偷看對手的真牌):
1. **對手範圍**:從剩下的牌抽一手對手牌 H,權重 = 對手在這之前每個決策點的策略機率乘積(依 H 的 bucket 查 checkpoint;如果對手已經換牌，只知道換幾張，就把所有「換這麼多張」的動作機率加起來)。這就是均衡玩家會做的貝氏推論。
2. **位置**:
   - 我方是 button(後換):對手的換牌已發生，照範圍推論補完對手換完後的牌。
   - 我方是大盲(先換):執行我方選項後，對手依 checkpoint 策略**看到我方換幾張再決定怎麼換**,所以對手的反應會跟著選項變。
3. **換牌後的下注**:雙方照 checkpoint 策略打完 postdraw(大盲先行動),所以位置劣勢、snow 的詐唬價值都會反映在 Q 裡。
4. 同時輸出「只看攤牌」的勝率(不含 postdraw 下注)當可解讀的對照。

**用途**
- 明顯錯誤 = 策略在 Q 明顯較低的選項上放了機率(差距超過 2 個 SE)。
- 局部遺憾值 = Q(最佳選項) − Q(策略的混合)。這是對 checkpoint「單步改進」能賺多少，等於 LBR(A2 第 12 節的選項 B)在換牌決策上的版本，可以當 draw phase 的品質指標。
- bucket 遺憾值：改用這個 Q,在真實的對手範圍和位置下重算。

**限制**
- 對手範圍和換牌後的下注都來自 checkpoint 自己的策略;策略沒訓練好(v2 的 draw 有 46% 是均勻)時，推出的範圍也不準。這是「相對於目前策略的單步改進」,不是對真實均衡的判斷。
- Monte Carlo 有雜訊，每個決策要幾百到幾千次模擬;只抽樣分析一部分決策(例如 500 個),成本在使用者筆電上約 [推測] 數十分鐘。

**推翻條件**:在已知的簡單局面(例如 made 7-5-4-3-2 面對任何範圍)Q 不支持 pat,代表實作有錯。

### 2.2 `candidate` 換牌模式不符合 max_draw=5 的規則 [確認，程式碼]
`solver/discard_actions.candidate_discard_actions` 只產生換 0–3 張的動作(`max_draw >= 3` 之後沒有換 4、5 張)。v1 / v2 用的是 `full`,不受影響;但任何「縮減動作」的實驗若直接用 `candidate`,等於改了遊戲規則。

### 2.3 明顯錯誤換牌的頻率(v1,`max_draw=1`)[確認]

只算「可避免」的錯誤(同一狀態存在不犯該錯的合法動作)。兩種可靠的錯誤:
- **拆掉已成的 7 以下低牌**(無對子、無順子同花、全部 ≤ 7,卻換牌)。
- **保留對子**(換牌後仍保留兩張同點數)。

「留大丟小」不可靠(可能是在拆順子聽牌),只當參考，不計入。下一步改用精確補牌勝率判定錯誤(見 2.1)。

| v1,20,000 局 self-play | 決策數 | 可避免錯誤機率 |
|---|---|---|
| 全部 draw 決策 | 30,086 | **15.1%** |
| 已訓練狀態 | 21,939 | 8.5% |
| 均勻(近似未訓練)狀態 | 6,581 | 35.0% |
| 查不到策略(均勻 fallback) | 1,566 | 24.4% |
| one pair,已訓練 | 8,167 | 22.8%(保留對子) |
| made 7 以下，已訓練 | 13 | 57.0%(拆掉成牌;狀態很少，靜態 28 個狀態也是 62%) |

讀法:
- 錯誤機率有一半以上來自未訓練或查不到的狀態(占 draw 決策的 27%)。主因是**訓練不足**,不是換牌邏輯錯。
- 已訓練狀態仍有 8.5% 錯誤，罕見狀態(made 7)尤其差 [推測：這些狀態的 strategy sum 很小，平均策略仍被早期均勻迭代主導]。

## 3. 提案

### P1(B2 可直接做，需核准):修正 `candidate` 模式的換牌張數
讓 `candidate_discard_actions` 在 `max_draw >= 4` 時也包含換 4、5 張的動作(例如各保留最佳 1–3 個)。
- 失敗模式:`max_draw=5` 下 candidate 模式少了合法動作。
- 測試：新增測試確認 `max_draw=5` 時每種張數都至少有一個動作;既有 checkpoint 不受影響(都用 `full`)。
- 推翻條件：無(規則問題)。

### P2(凍結介面，需走 version bump 與重訓):bucket 加入順子聽牌資訊
| 方案 | 無對子模式數 | 增加 |
|---|---|---|
| 目前 | 140 | — |
| R2:加 5 個旗標「丟位置 i 後剩下四張是否為順子聽牌」 | 187 | +34% |
| R3:R2 + 8 和 9 分開 | 243 | +74% |
| 完整點數 | 1,278 | ×9.1 |

day57 更正後的建議：先看完整的 bucket 遺憾值;目前證據指向 R3 中「8 與 9 分開」那一部分(面對 pat 對手時遺憾值最大),而不是順子聽牌旗標。只影響 predraw / draw 的 key(v2 中約占資訊集的 15%),[推測] 總資訊集增加約 5–11%。
- 失敗模式：同一 bucket 內正確換牌不同(2.1)。**目前證據不足**:要先用 bucket 遺憾值確認損失夠大。
- 驗證：同 seed、同迭代數訓練 R2 vs 現行，用 A2 benchmark 比 SBR 下界、draw 的 played 均勻比例與可避免錯誤。
- 推翻條件:R2 的 SBR 下界沒有顯著降低(< 2 SE),且 draw 可避免錯誤沒有下降。
- 這會讓所有 checkpoint 失效，要和 C1 的重訓排程一起。

### P3(ablation,不保證行為不變):移除明顯被支配的換牌動作
- 內容:draw 動作只保留「不保留對子」的動作(若存在),made 7 以下只保留 pat。[推測] 每個 draw 節點的平均動作數大幅下降，未訓練狀態的均勻機率不再浪費在明顯錯誤上，收斂應較快。
- 前提:P1 修好(或另寫縮減規則)。
- **評估時的注意事項**:目前 `evaluate_checkpoint` 的 SBR 用 checkpoint 自己的動作集合，縮減版 checkpoint 的 response 也被縮減，量到的是另一個遊戲的下界。ablation 需要「response 用完整 32 個動作、profile 在被移除的動作上機率為 0」的評估模式(A2 要加的功能)。
- 推翻條件：同迭代數下，縮減版在完整動作的 SBR 下界比 full 版高 2 SE 以上。

### 優先順序建議
1. 訓練不足是 draw 錯誤的主因 → 先等 A1 / C1 能跑更多迭代(A1 已把記憶體降到可跑 40k)。
2. P1(小、無風險)。
3. P2 和 C1 的下一次重訓一起做。
4. P3 需要 A2 先加「完整動作 response」評估，再做 ablation。

## 4. 不做的事
- 沒有改任何 solver 檔案或 checkpoint。
- 「留大丟小」不當錯誤指標(2.1)。
- snow(拿爛牌 pat 當詐唬)只列頻率，不當錯誤:適量 snow 是合理策略。
