# 提案:external sampling 的平均策略累積權重(day74,待核准)

標記:**[確認]** = 程式碼或推導確認;**[推測]** = 推論;**[實測]** = 雲端小實驗。

## 1. 現象 [確認，程式碼]
`solver/cfr_trainer.py` `_external_sampling_cfr`:平均策略只在**正在更新的玩家(traverser)自己的節點**累積，權重是自己的到達機率:

```python
node.accumulate_strategy(realization_weight=traverser_reach)
```

這段和 `_full_cfr`(完整走訪)的寫法一樣。完整走訪時這是正確的;external sampling 時不是。

## 2. 為什麼和 CFR 的定義不一致 [確認，推導]
CFR 的收斂保證是對這個平均策略成立:

  σ̄(I) = Σ_t π_i^t(I) σ^t(I) / Σ_t π_i^t(I)  (只用**自己的**到達機率 π_i 加權)

external sampling 裡，發牌(chance)和對手的動作是抽樣的。節點 I 在第 t 次被走到的機率是 π_c(I) · π_{-i}^t(I)。所以目前程式每次累積的**期望值**是

  π_c(I) · π_{-i}^t(I) · π_i^t(I) · σ^t(I)

多了一個 **π_{-i}^t(I)**(對手在第 t 次走到這裡的機率)。它會隨著對手策略改變，所以不是常數，平均的權重被扭曲：對手**比較常走到 I 的那些迭代**權重比較大。

訓練初期雙方都接近均勻，會頻繁走到之後很少走的路線(例如大加注、all-in 之後)。這些早期、接近均勻的策略在那些節點上權重過大，平均策略會被拉向均勻，而且要很多次迭代才會被稀釋掉(比例約 1/T)。

[推測] 這可能是「換牌階段平均策略一直接近均勻、current-vs-average 不下降」的原因之一:換牌節點分在 504 個公開節點、每個都在下注路線之後，受對手路線機率變化的影響最大。這只是推測，要用第 5 節的實驗驗證。

## 3. 修正(Lanctot et al. 2009 的 simple averaging)
平均策略改在**對手的節點**累積：對手節點的動作本來就照 σ^t 抽樣，加上 current strategy、權重 1。期望值是 π_c · π_j^t(I) · σ^t(I),也就是正確的自己到達機率(π_c 對同一個節點是常數)。

- 計算量不變(對手節點本來就要算 current strategy)。
- 不改 info set key、不改 checkpoint 格式;但存下來的平均策略數值會不同，**要重訓**。
- `_full_cfr` 不動。

## 4. [實測] 小實驗：同一次訓練，兩種平均
fast sizing、`max_draw=5`、bucket、seed 42、300 次(雲端 155 秒,66,562 節點)。regret 和抽樣完全相同，只有平均方式不同。在 39,722 個兩邊都有平均的節點(未加權平均):
- 兩種平均策略的距離(TV)平均 0.040。
- 離均勻的距離：目前的方式 0.012,simple averaging 0.044。

只代表兩者確實不同;300 次太少，不能說哪個比較好。

## 5. 驗證方式(提案)
1. 單元測試：在一個 info set 的到達機率會隨對手變化的情況下，兩種方式的期望權重(可以手算的小例子)。
2. **同一次訓練記錄兩種平均**(單一變因):fast sizing、`max_draw=5`、seed 42、4,000–8,000 次，在雲端背景跑(約 0.5 秒 / 次)。存兩份 checkpoint,用 A2 的評估(SBR、均勻比例、baselines)比較。
3. 固定 seed 的指紋：regret 表和節點數必須和修正前完全相同(只有平均不同)。

**什麼結果代表提案錯了**:simple averaging 的 SBR 和均勻比例沒有比目前的方式好(在雜訊內相同或更差)。那就維持現狀，只在文件記錄這個理論差異。

## 6. 之後
通過的話：改成 simple averaging(或兩者都存、預設 simple),C1 從 0 重訓一次。這是單一變因，可以和之後的其他改動(例如 Linear CFR 加權)分開評估。

## 7. [實測] 結果(day74,雲端)
設定：fast sizing、`max_draw=5`、bucket、stack 20、seed 42、external sampling,單次訓練同時記錄兩種平均(`scripts/compare_average_modes.py`;指紋和原 trainer 相同)。8,000 次 4,339 秒,358,987 節點。評估：A2 `standard`、seed 2027,simple 那份加 `--previous` 對打 current。報告在 `experiments/average_modes/eval/`。

策略距離(兩邊都有平均的節點，依 simple 的拜訪次數加權):

判讀:
- **[證據] 8k 時 simple 在每個階段的近均勻比例都比較低**(draw 36% → 26%),而且未拜訪節點存成均勻這點只會讓 simple 吃虧。vs uniform 高 0.34(約 2 SE),vs call_station 高 0.27(約 1.3 SE)。
- **[證據] SBR 分不出差別**:3.71 vs 3.76,差距遠小於單次驗證 SE 約 0.6。標準 preset 本來就測不出小於約 0.4 chips/deal 的差異(CLAUDE.md 已知限制)。
- **[證據] 對打不顯著**:2k +0.22 ± 0.12(1.8 SE),8k +0.08 ± 0.13。
- 2k 結果有好有壞(postdraw 近均勻和 vs uniform 比較差);太早期，雜訊大。
- **沒有任何指標在 8k 顯著變差。**

對照第 5 節的否證條件:「SBR **和**均勻比例都沒有比較好」→ 均勻比例有比較好，所以提案**沒有被否證**;但 SBR(唯一的可剝削度指標)也沒有證明它比較好。結論：理論上正確(CFR 的收斂保證是對 π_i 加權平均成立)、零額外計算、實測至少不差、品質指標偏好它。

## 8. 建議(待使用者決定)
1. 在 trainer 加 `average_mode`("reach" = 目前，"simple"),預設維持 "reach",所以既有指紋和測試不變;C1 manifest 記錄這個設定。
2. 加單元測試(第 5 節第 1 點)和指紋測試(兩種模式 regret 表相同)。
3. 不為了這一項單獨重訓 C1;先在雲端用同樣的小實驗做 Linear CFR(第 2 項),兩者都通過後，C1 用新設定重訓一次。
